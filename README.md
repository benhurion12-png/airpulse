# AirPulse

Пошаговая инструкция для Ксении и Артёма: как получить проект через Git, создать локальные секреты, запустить все сервисы в Docker и подключить настоящий MQ‑2 к ESP32.

AirPulse — учебная IoT‑система мониторинга качества воздуха в Северо‑Казахстанской области. Клиент написан на Next.js, backend API — на NestJS 12 и TypeScript. Система принимает показания виртуальных и реальных датчиков, сохраняет их в PostgreSQL через TypeORM, рассчитывает индекс качества `0–100`, строит прогноз и показывает объекты на карте.

## 1. Что нужно установить

Для обычного демонстрационного запуска нужны:

1. **Git** — чтобы скачать проект.
2. **Docker Desktop** — чтобы одной командой запустить базу, MQTT, API, симулятор и сайт.
3. Современный браузер: Chrome, Edge или Firefox.

Для реального MQ‑2 дополнительно нужны:

1. VS Code.
2. Расширение **PlatformIO IDE**.
3. Драйвер CH340, если плата ESP32 не появляется как COM‑порт.
4. ESP32, модуль MQ‑2, USB‑кабель с передачей данных и безопасный делитель напряжения.

Для разработки без Docker дополнительно установите Node.js 22 LTS. Python нужен только отдельному демонстрационному симулятору; основной API Python не использует.

Проверьте основные программы в PowerShell:

```powershell
git --version
docker --version
docker compose version
```

Если Docker отвечает ошибкой, сначала запустите Docker Desktop и дождитесь состояния **Engine running**.

## 2. Как получить проект через Git

### Если репозиторий публичный

Токен не нужен. Откройте PowerShell в папке, где хотите хранить проект:

```powershell
git clone https://github.com/ИМЯ_ВЛАДЕЛЬЦА/airpulse.git
cd airpulse
```

Замените ссылку на настоящий адрес репозитория.

### Если репозиторий приватный

У пользователя должен быть доступ к репозиторию. GitHub при клонировании по HTTPS может запросить имя пользователя GitHub и **Personal Access Token (PAT)** вместо пароля.

PAT — это токен GitHub. Он не является JWT AirPulse и не должен записываться в `.env` проекта. Для постоянной работы удобнее настроить SSH‑ключ:

```powershell
git clone git@github.com:ИМЯ_ВЛАДЕЛЬЦА/airpulse.git
cd airpulse
```

### Если владелец ещё не опубликовал проект

Владелец выполняет это один раз из корня проекта:

```powershell
git init
git add .
git commit -m "Initial AirPulse project"
git branch -M main
git remote add origin https://github.com/ИМЯ_ВЛАДЕЛЬЦА/airpulse.git
git push -u origin main
```

Файлы `.env` и `firmware/esp32-mq2/secrets.h` специально находятся в `.gitignore`. Они содержат локальные секреты и не должны попадать в Git. После каждого нового клонирования их создают заново из шаблонов.

## 3. Создание `.env`

Находясь в корне `airpulse`, выполните:

```powershell
Copy-Item .env.example .env
```

В macOS или Linux:

```bash
cp .env.example .env
```

Для первого запуска на одном компьютере можно оставить учебные значения из шаблона:

```dotenv
POSTGRES_PASSWORD=airpulse-local-only
DB_SYNCHRONIZE=true
ADMIN_KEY=airpulse-admin
SIMULATOR_TOKEN=airpulse-simulator
JWT_SECRET=replace-with-a-long-random-string-at-least-32-characters
JWT_ACCESS_MINUTES=30
JWT_REFRESH_DAYS=7
ADMIN_EMAIL=admin@airpulse.local
ADMIN_PASSWORD=ChangeMe123!
ADMIN_NAME=Администратор AirPulse
SENSOR_INTERVAL_SECONDS=15
NEXT_PUBLIC_API_URL=http://localhost:8000
APP_ORIGINS=http://localhost:3000,http://127.0.0.1:3000
```

| Переменная | Для чего нужна |
|---|---|
| `POSTGRES_PASSWORD` | Пароль пользователя PostgreSQL внутри Docker. |
| `DB_SYNCHRONIZE` | В учебном стенде разрешает TypeORM создать недостающие таблицы. Для production используйте миграции и значение `false`. |
| `ADMIN_KEY` | Служебный ключ для HTTP‑телеметрии и совместимости с внутренними запросами. В браузер не передаётся. |
| `SIMULATOR_TOKEN` | Ключ, по которому симулятор получает список виртуальных датчиков. |
| `JWT_SECRET` | Секрет, которым API подписывает JWT. Используйте длинную случайную строку и никому её не сообщайте. |
| `JWT_ACCESS_MINUTES` | Срок жизни короткого access‑токена в минутах. |
| `JWT_REFRESH_DAYS` | Срок жизни refresh‑токена в днях. |
| `ADMIN_EMAIL` | Email первого администратора, которого API создаёт автоматически. |
| `ADMIN_PASSWORD` | Пароль первого администратора. Перед общим запуском обязательно замените. |
| `ADMIN_NAME` | Имя первого администратора в интерфейсе. |
| `SENSOR_INTERVAL_SECONDS` | Как часто симулятор отправляет показания. Минимум в коде — 2 секунды. |
| `NEXT_PUBLIC_API_URL` | Адрес API, к которому обращается браузер. |
| `APP_ORIGINS` | Адреса сайта, которым API разрешает запросы через CORS. |

Для проекта, доступного другим людям, замените `POSTGRES_PASSWORD`, `ADMIN_KEY`, `SIMULATOR_TOKEN`, `JWT_SECRET` и `ADMIN_PASSWORD`. Случайный секрет можно получить в PowerShell:

```powershell
[Convert]::ToBase64String([Security.Cryptography.RandomNumberGenerator]::GetBytes(48))
```

После изменения `.env` пересоберите контейнеры:

```powershell
docker compose --profile demo up --build -d
```

> Первый администратор создаётся только при отсутствии пользователя с `ADMIN_EMAIL`. Если база уже запускалась, простая замена `ADMIN_PASSWORD` в `.env` не изменит старый пароль. Для чистой учебной установки можно удалить том командой `docker compose down -v`, но она также удалит все показания и созданные объекты.

## 4. Клиент, регистрация, роли и JWT

Да, клиент — это сайт Next.js из папки `web`. После запуска он открывается по адресу <http://localhost:3000>. На первой странице есть две вкладки: **«Вход»** и **«Регистрация»**.

### Как войти администратору

Используйте `ADMIN_EMAIL` и `ADMIN_PASSWORD` из своего `.env`. В шаблоне для первого локального запуска это:

```text
Email:  admin@airpulse.local
Пароль: ChangeMe123!
```

Это демонстрационные данные. Ксения и Артём должны заменить пароль в `.env` **до первого запуска** общей базы.

### Как зарегистрировать обычного пользователя

1. Откройте <http://localhost:3000>.
2. Выберите **«Регистрация»**.
3. Укажите имя, email и пароль не короче восьми символов. В пароле должна быть хотя бы одна буква и одна цифра.
4. Нажмите **«Зарегистрироваться»**. Вход выполнится автоматически.

Повторная регистрация того же email запрещена. Email сохраняется в нижнем регистре. Новый аккаунт всегда получает безопасную роль **«Клиент»**.

### Что разрешено ролям

| Роль | Возможности |
|---|---|
| `CLIENT` — Клиент | Просматривать обзор, карту, карточки, датчики, прогноз и уведомления. |
| `OPERATOR` — Оператор | Всё как у клиента, плюс добавлять объекты и датчики и менять режим датчиков. |
| `ADMIN` — Администратор | Всё как у оператора, плюс видеть пользователей, менять их роли и включать/отключать аккаунты. |

Чтобы выдать права: администратор входит в систему, нажимает аватар, выбирает **«Управление пользователями»**, затем меняет роль пользователя на **«Оператор»** или **«Администратор»**. Собственную роль и активность администратор случайно изменить не сможет.

### Как работают JWT

После входа API выдаёт два подписанных токена:

- access JWT действует по умолчанию 30 минут и прикладывается к защищённым запросам;
- refresh JWT действует по умолчанию 7 дней и незаметно получает новую пару токенов после истечения access JWT.

Токены создаются автоматически — готовый JWT **не нужно** записывать в `.env`. В `.env` хранится только `JWT_SECRET`, то есть ключ подписи. В учебной версии токены сохраняются в `localStorage` браузера; кнопка **«Выйти»** удаляет их.

Не путайте:

- GitHub PAT — доступ к приватному Git‑репозиторию;
- access/refresh JWT — временный вход конкретного пользователя в AirPulse;
- `JWT_SECRET` — секрет сервера, которым подписываются JWT;
- `ADMIN_KEY` — внутренний служебный ключ, который не встраивается в сайт;
- `SIMULATOR_TOKEN` — ключ внутреннего симулятора;
- MQTT сейчас работает без логина только внутри локального учебного стенда.

## 5. Самый простой запуск в Docker

Запустите все сервисы вместе с виртуальными датчиками:

```powershell
docker compose --profile demo up --build
```

Первый запуск может занять несколько минут: Docker скачивает базовые образы и устанавливает зависимости. Для запуска в фоне добавьте `-d`:

```powershell
docker compose --profile demo up --build -d
```

Есть также готовый PowerShell‑скрипт. Он сам создаст `.env`, если файла ещё нет:

```powershell
.\scripts\start.ps1
```

После запуска откройте:

- интерфейс AirPulse: <http://localhost:3000>;
- документацию API Swagger: <http://localhost:8000/docs>;
- проверку API: <http://localhost:8000/api/health>.

Сначала войдите администратором из `.env` или зарегистрируйте аккаунт клиента. Без входа данные мониторинга не открываются.

Проверьте контейнеры:

```powershell
docker compose --profile demo ps
```

У сервисов `postgres` и `api` должен появиться статус `healthy`, остальные должны быть `running`.

## 6. Какие контейнеры запускаются

| Сервис | Назначение | Порт компьютера |
|---|---|---:|
| `postgres` | Хранит пользователей, объекты, датчики и историю показаний. | `5436` только на localhost |
| `mosquitto` | MQTT‑брокер принимает телеметрию. | `1886` |
| `api` | NestJS 12 + TypeORM: авторизация, расчёт индекса, история, MQTT и ML‑прогноз. | `8000` |
| `simulator` | Публикует виртуальные показания. Запускается профилем `demo`. | нет |
| `web` | Интерфейс Next.js. | `3000` |

Внутри Docker сервисы используют другие адреса: API подключается к `postgres:5432` и `mosquitto:1883`. С компьютера и ESP32 используются опубликованные порты `5436` и `1886`.

При первом старте API автоматически создаёт таблицы, первого администратора и четыре демонстрационных объекта с 48 часами истории. Данные сохраняются в Docker‑томе `airpulse_postgres_data` и не исчезают после обычного перезапуска.

## 7. Как работает вся система

Поток виртуальных данных:

```text
Пользователь ──email/пароль──► API ──access + refresh JWT──► Web-интерфейс

Симулятор
  │  1. Получает список SIMULATED-датчиков по HTTP и SIMULATOR_TOKEN
  │  2. Публикует JSON в MQTT
  ▼
Mosquitto ──► NestJS API ──► PostgreSQL ──► Web-интерфейс
                        │                 │
                        ├─ индекс 0–100   ├─ карта и карточки
                        ├─ история        ├─ уведомления
                        └─ ML-прогноз     └─ настройки браузера
```

Поток реального MQ‑2:

```text
MQ-2 ──аналоговый сигнал──► ESP32
ESP32 ──Wi-Fi / MQTT:1886──► Mosquitto
Mosquitto ──► API ──► PostgreSQL ──► сайт
```

MQTT‑топик:

```text
airpulse/devices/<DEVICE_ID>/telemetry
```

Пример сообщения:

```json
{
  "deviceId": "mq2-real-001",
  "type": "MQ2",
  "value": 245.7,
  "unit": "ppm",
  "source": "REAL"
}
```

API принимает сообщение только когда одновременно совпадают:

1. `DEVICE_ID` в прошивке;
2. ID датчика, созданного в AirPulse;
3. ID внутри MQTT‑топика;
4. тип `MQ2`;
5. режим датчика `REAL`;
6. источник сообщения `REAL`.

## 8. Индекс качества и прогноз

Для каждого типа датчика задано три порога. Концентрация переводится в оценку:

- до хорошего порога: `100 → 85`;
- от хорошего до повышенного: `85 → 50`;
- от повышенного до опасного: `50 → 0`;
- выше опасного порога: `0`.

Индекс объекта — среднее оценок только тех датчиков, которые установлены на объекте и имеют данные. Если установлен один PM2.5, индекс рассчитывается только по PM2.5.

Прогноз использует до 192 последних измерений каждого параметра за 48 часов. Для каждого параметра строится линейная регрессия, прогнозируется значение через 60 минут, затем прогнозные концентрации снова переводятся в общий индекс. Это демонстрационный трендовый прогноз, а не сертифицированное заключение о безопасности воздуха.

## 9. Уведомления и настройки

Раздел **«Уведомления»** формирует события из текущего состояния:

- индекс объекта ниже заданного порога;
- по объекту нет данных;
- датчик не выходил на связь больше пяти минут.

Нажатие на уведомление открывает соответствующий объект. Состояние «прочитано» сохраняется в `localStorage` этого браузера.

В **«Настройках»** можно выбрать:

- светлую или тёмную тему;
- обновление каждые 10, 15, 30 или 60 секунд;
- порог тревоги `0–100`;
- уведомления о качестве воздуха;
- уведомления о потере связи с датчиками.

Эти настройки сохраняются только в текущем браузере. Они не меняют `.env`, Docker или настройки другого пользователя.

## 10. Подключение настоящего MQ‑2

### Шаг 1. Безопасно подключите модуль

У ESP32 аналоговый вход рассчитан максимум на **3.3 В**. Аналоговый выход некоторых модулей MQ‑2 может приближаться к 5 В. Нельзя подключать AO такого модуля к GPIO34 напрямую.

Минимальная схема:

```text
MQ-2 VCC  ──► питание по спецификации вашего модуля
MQ-2 GND  ──► GND ESP32
MQ-2 AO   ──► делитель напряжения ──► GPIO34 ESP32
GPIO34    ──► внешний резистор 100 кОм ──► GND
```

Перед включением проверьте мультиметром, что на GPIO34 никогда не приходит больше 3.3 В. Если вы не уверены в схеме делителя, попросите преподавателя или специалиста проверить подключение. Неправильное напряжение может повредить ESP32.

### Шаг 2. Запустите AirPulse

Можно оставить демонстрационный симулятор включённым: он автоматически пропускает датчики в режиме `REAL`.

```powershell
docker compose --profile demo up --build -d
```

Если виртуальные датчики не нужны:

```powershell
docker compose up --build -d
```

или:

```powershell
.\scripts\start.ps1 -NoSimulator
```

### Шаг 3. Создайте датчик в интерфейсе

1. Откройте <http://localhost:3000>.
2. Войдите как **Оператор** или **Администратор**. У роли «Клиент» кнопки добавления нет.
3. Перейдите в **«Датчики»**.
4. Нажмите **«Добавить»**.
5. Укажите ID, например `mq2-real-001`.
6. Тип — `MQ2`.
7. Режим — **«Реальный»**.
8. Выберите объект и сохраните.

Запомните ID: в прошивке он должен быть написан абсолютно так же, включая регистр, дефисы и цифры.

### Шаг 4. Узнайте IP компьютера

ESP32 нельзя направлять на `localhost`: для платы это означало бы саму ESP32. Нужен IPv4‑адрес компьютера, на котором работает Docker.

```powershell
ipconfig
```

Найдите активный Wi‑Fi или Ethernet‑адаптер и строку **IPv4 Address**, например `192.168.1.100`.

ESP32 и компьютер должны находиться в одной локальной сети. Гостевая Wi‑Fi‑сеть или мобильная точка доступа может запрещать обмен между устройствами.

### Шаг 5. Разрешите MQTT в файрволе

Windows может спросить разрешение при первом запуске Docker — разрешите доступ для частной сети. Если ESP32 не подключается, откройте входящий TCP‑порт `1886` в PowerShell от имени администратора:

```powershell
New-NetFirewallRule -DisplayName "AirPulse MQTT 1886" -Direction Inbound -Protocol TCP -LocalPort 1886 -Action Allow
```

Не открывайте этот порт в интернет через роутер. Он нужен только внутри доверенной локальной сети.

### Шаг 6. Создайте локальный файл секретов прошивки

```powershell
Copy-Item firmware\esp32-mq2\secrets.example.h firmware\esp32-mq2\secrets.h
```

Откройте `firmware/esp32-mq2/secrets.h` и заполните:

```cpp
const char* WIFI_SSID = "ИМЯ_ВАШЕЙ_WIFI";
const char* WIFI_PASSWORD = "ПАРОЛЬ_WIFI";
const char* MQTT_HOST = "192.168.1.100";
const uint16_t MQTT_PORT = 1886;
const char* DEVICE_ID = "mq2-real-001";
```

`secrets.h` находится в `.gitignore`. Не добавляйте его в Git и не отправляйте скриншоты с паролем.

### Шаг 7. Загрузите прошивку через PlatformIO

1. Подключите ESP32 USB‑кабелем.
2. В VS Code выберите **File → Open Folder** и откройте именно папку `airpulse/firmware`.
3. Дождитесь, пока PlatformIO установит платформу и библиотеки.
4. Нажмите **Upload** в нижней панели PlatformIO.
5. Откройте **Serial Monitor** со скоростью `115200`.

То же самое из терминала PlatformIO:

```powershell
cd firmware
pio run
pio run --target upload
pio device monitor --baud 115200
```

Если порт не определяется автоматически, добавьте в `[env:esp32dev]` файла `firmware/platformio.ini` строку:

```ini
upload_port = COM3
```

Замените `COM3` на порт из Windows Device Manager.

### Шаг 8. Проверьте результат

В Serial Monitor ожидаются сообщения:

```text
Wi-Fi: connecting ... connected
MQTT: connecting to 192.168.1.100:1886 ... connected
MQ-2 warm-up ...
MQ-2 [mq2-real-001]: 245.70 ppm (real), MQTT publish=ok
```

Прошивка ждёт 60 секунд прогрева. При отключённом датчике, значении АЦП у границы диапазона или во время прогрева данные не отправляются.

Проверьте логи сервера:

```powershell
docker compose logs -f api mosquitto
```

После первой принятой посылки датчик появится онлайн в AirPulse. Для точных физических измерений MQ‑2 требует полноценного прогрева и калибровки `r0`; формула в прошивке является демонстрационным приближением.

## 11. Доступ с другого компьютера или телефона

Допустим, IP компьютера с Docker — `192.168.1.100`. В `.env` укажите:

```dotenv
NEXT_PUBLIC_API_URL=http://192.168.1.100:8000
APP_ORIGINS=http://192.168.1.100:3000,http://localhost:3000,http://127.0.0.1:3000
```

Пересоберите сайт:

```powershell
docker compose --profile demo up --build -d
```

## 15. Частые проблемы

### Сайт пишет «AirPulse API недоступен»

```powershell
docker compose ps
docker compose logs api postgres
```

Проверьте <http://localhost:8000/api/health>.

### Объекты есть, но значения не меняются

```powershell
docker compose --profile demo ps
docker compose logs simulator
docker compose --profile demo up -d simulator
```

### После изменения `.env` ничего не изменилось

Публичные переменные Next.js встраиваются при сборке:

```powershell
docker compose --profile demo up --build -d
```

### Не получается войти администратором

Проверьте `ADMIN_EMAIL` и `ADMIN_PASSWORD`. Эти значения создают администратора только при первом старте пустой базы. Если пароль поменяли уже после запуска, верните первоначальный пароль или полностью сбросьте учебную базу командой `docker compose down -v`, а затем запустите проект заново. Сброс удалит все локальные данные.

### После регистрации нет кнопки «Добавить»

Это нормально: новый пользователь имеет роль «Клиент». Администратор должен открыть свой профиль → **«Управление пользователями»** и выдать этому аккаунту роль «Оператор» или «Администратор».

### ESP32 постоянно пишет `MQTT failed`

Проверьте:

1. `MQTT_HOST` — IP компьютера, а не `localhost`.
2. Порт — `1886`.
3. Компьютер и ESP32 в одной сети.
4. Docker Desktop запущен.
5. Mosquitto работает: `docker compose ps mosquitto`.
6. Файрвол разрешает входящий TCP `1886`.

### MQTT подключён, но датчик остаётся офлайн

Сравните `DEVICE_ID` в `secrets.h` и ID в AirPulse. Проверьте тип `MQ2`, режим `REAL`, сообщение `publish=ok` и логи `docker compose logs -f api`.

### ESP32 не появляется как COM‑порт

Используйте USB‑кабель с передачей данных, установите драйвер CH340, попробуйте другой USB‑порт и проверьте Windows Device Manager.

### Карта без подложки

Карта получает тайлы OpenStreetMap через интернет. Маркеры продолжат работать, но без доступа к `tile.openstreetmap.org` фон карты не загрузится.

## 17. Правила безопасности

1. Никогда не коммитьте `.env` и `secrets.h`.
2. Не публикуйте Wi‑Fi‑пароль, GitHub PAT, `JWT_SECRET`, `ADMIN_PASSWORD`, `ADMIN_KEY`, `SIMULATOR_TOKEN` или JWT из браузера в сообщениях и скриншотах.
3. Если секрет когда‑то попал в Git, простого удаления из нового коммита недостаточно: замените секрет и при необходимости очистите историю репозитория.
4. MQTT без пароля используйте только в доверенной локальной сети.
5. Не выводите Docker‑порты напрямую в интернет.
6. Пользовательская авторизация и JWT уже есть, но для реального размещения переведите сайт на HTTPS, храните refresh‑токен в защищённой HttpOnly cookie, добавьте отзыв сессий, ограничение попыток входа, восстановление пароля, MQTT‑аутентификацию и TLS.

После этих шагов Ксения и Артём могут независимо клонировать репозиторий, создать собственные локальные секреты, запустить демонстрацию и подключить реальный MQ‑2 без передачи чужих паролей.
