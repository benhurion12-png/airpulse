# ESP32 CH340 + MQ-2

## Загрузка через PlatformIO

1. Откройте в VS Code именно папку `firmware`, в которой находится `platformio.ini`.
2. Скопируйте `esp32-mq2/secrets.example.h` в `esp32-mq2/secrets.h` и укажите там свои `WIFI_SSID`, `WIFI_PASSWORD`, `MQTT_HOST` и явный `DEVICE_ID`.
3. Подключите ESP32 через USB и дождитесь появления COM-порта.
4. В панели PlatformIO нажмите **Upload**. COM-порт определяется автоматически.
5. Для просмотра сообщений платы нажмите **Serial Monitor**; скорость уже настроена на `115200`.

`DEVICE_ID` не создаётся автоматически. Задайте его в `secrets.h` вручную, например
`mq2-real-001`, и используйте точно такой же ID при регистрации реального MQ-2 в
AirPulse. Показания принимаются только при совпадении ID в реестре AirPulse,
MQTT-топике и JSON-сообщении.

Если автоматический выбор порта не сработал, добавьте в секцию `[env:esp32dev]`
файла `platformio.ini` строку `upload_port = COM3`, заменив `COM3` на порт вашей платы.

1. В AirPulse откройте «Датчики», добавьте датчик типа **MQ2** в режиме **Реальный** и задайте ему тот же ID, который указан в `DEVICE_ID` прошивки.
2. Установите в Arduino IDE поддержку ESP32 и библиотеки `PubSubClient`, `ArduinoJson`.
3. Заполните `secrets.h`: Wi-Fi, IP компьютера с Docker и ID устройства. Внешний порт MQTT — `1886`.
4. Выберите плату `ESP32 Dev Module` и COM-порт CH340, затем загрузите прошивку.
5. MQ-2 требует прогрева и калибровки. Аналоговый выход 5-вольтового модуля нельзя подавать на ESP32 напрямую — используйте делитель до 3.3 В. Добавьте резистор `100 кОм` от GPIO34 к GND: тогда при физическом отключении MQ‑2 вход гарантированно уходит к нулю.

Если вход GPIO34 отключён, сигнал зажат на границе АЦП или ещё идёт прогрев, прошивка ничего не публикует. При валидном сигнале отправляется расчётное реальное значение с источником `REAL`.
